# Agent, workflow and memory

The state machine records INTAKE → UNDERSTAND → RETRIEVE → PLAN → ACT → VERIFY → RESPOND → COMPLETE, with ESCALATE, FAILED and cancellation paths. Nodes may perform retrieval before structured understanding according to their ordered definition; trace order reflects execution, not an invented reasoning transcript. Public plans state intended checks, tools and evidence. Private chain of thought is neither requested nor saved.

Two versioned workflows, Customer Support QA and Return / Refund, support v1/v2 and actual unified diffs. Validated node types are Input, Retrieve, LLM, Tool, Condition, Approval and Output. Workflows are sequential, not general DAGs. Input must be first, Output last; exactly one intent node and an approval gate are required. Retrieve configuration controls mode/top K unless the run explicitly overrides them. Tool nodes use the allowlist; conditions test category and can stop/escalate. Replay takes a version snapshot and creates a fresh run/proposal, never copies human approval.

Native tools include customer/order/inventory lookup, knowledge search, active policy lookup, note creation, eligibility checks, proposals and escalation. `cancel_order` deliberately creates a cancellation proposal. There is no model-callable execute-refund tool. Model arguments cannot choose staff identity or conversation customer scope. Low-risk writes require operator/admin and idempotency; high-risk actions require a separate approver/admin decision.

Refund planning reads order and active policy, checks the delivered-age rule and creates a proposal. Replacement additionally reads inventory and troubleshooting, exposes recorded serial number and asks the reviewer to assess exclusions; it cannot physically diagnose a device. Approval reruns eligibility and checks order/policy versions. The independent BusinessVerifier rereads the resulting order/refund/replacement and records evidence before a completed action claim. Submitted refund is distinguished from bank settlement.

Conversation messages are persisted for the console. Case/preference/operational memory is separate, source-attributed, timestamped, scoped and expiring. Operator-confirmed facts can be created, invalidated and deleted; model guesses are not auto-saved. Expired/invalid facts are excluded at read time. Memory-on/off changes whether a confirmed serial number is asked again. The seeded serial is synthetic, not a real user fact. Free-form historical message compression is not implemented.

The multi-agent option performs an actual second provider call to an Order, Policy or Technical specialist, compares structured routing and sends disagreements to clarification, then composes grounded observations. This narrow topology is intentionally assessable. Its Fake-provider score matches the single-agent full system; it is not evidence that multi-agent reasoning improves real LLM quality. Real-model specialist prompts and token efficiency remain unmeasured.
