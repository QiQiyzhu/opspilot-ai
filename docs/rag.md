# Retrieval design and experiment interpretation

The pipeline accepts Markdown, TXT, HTML and section-object JSON. HTML scripts/styles/iframes are removed; document size is bounded. Headings define sections, section text is split into overlapping word windows, and every chunk stores document ID, chunk ID, title, section, text, policy version, effective date and metadata. The document retains content SHA-256 and embedding model identity. Expired, future and inactive document versions are excluded in every retrieval mode.

`BAAI/bge-small-en-v1.5` is executed through FastEmbed/ONNX Runtime on CPU with 384 dimensions and two inference threads. It is an English embedding model; the project does not claim multilingual semantic quality. Files are downloaded once into configurable `OPSPILOT_MODEL_CACHE`, then inference runs locally. Dense ranking uses PostgreSQL pgvector cosine distance. The small corpus uses exact distance, not an approximate vector index.

Baselines are BM25 lexical ranking, dense cosine, reciprocal rank fusion (RRF) of lexical+dense with metadata filtering, and hybrid plus **lexical-feature-v1** reranking. RRF uses `1/(60+rank)` for each rank list. The reranker combines query-token coverage, title/section overlap and vector similarity. It is a reproducible non-model scorer, not a cross encoder. The trace records candidates, component scores, final context, filters and timing.

Runtime retrieval caching fingerprints query/config plus currently effective document IDs. Activation changes invalidate the key; a 30-second TTL bounds retention. Redis failure selects an LRU-like 128-entry local cache with TTL and a circuit delay. Offline RAG experiments bypass this cache and clear query-vector memoization per case to avoid comparing a cold dense query against a warm hybrid query.

The 30-case [frozen retrieval set](../evals/data/rag-v1.json) contains 26 answerable and 4 no-answer questions. Gold document+section labels are hand-authored from simulated policy text, AI-reviewed and **PENDING HUMAN REVIEW**. Recall and reciprocal rank use the first correct section rank. nDCG treats one gold section as relevant. No-answer abstention is reported separately, not mixed into Recall. This is a development corpus, not held-out external evidence.

The four actual baselines and a 36-configuration experiment (40/100/240 word chunks × four modes × top K 3/5/10) are in `evals/reports`. Rechunking experiments build a real PostgreSQL temporary vector table and perform actual ONNX inference; they never alter the production corpus. Medium and large chunks become identical when a source section is shorter than either window. This limits the conclusion: the experiment does not prove that larger chunks are generally worse.

The retained runtime default is 100-word, section-preserving chunks and hybrid lexical rerank, top K 5: it preserves full small policy sections, improves first-result ordering on this corpus and retains all answerable gold sections at K5. Hybrid without rerank has stronger K3 coverage. Forty-word reranked chunks have slightly higher MRR but fragmented evidence and more chunks; the small difference needs held-out confirmation. No-answer abstention remains weak and is an explicit failure area. Deterministic out-of-scope routing and server authorization reduce action risk but cannot establish that every answer is relevant.

Primary references accessed 2026-09-10: [pgvector](https://github.com/pgvector/pgvector), [FastEmbed](https://github.com/qdrant/fastembed), [BGE model card](https://huggingface.co/BAAI/bge-small-en-v1.5). Model quality claims beyond measured local cases are not made.
